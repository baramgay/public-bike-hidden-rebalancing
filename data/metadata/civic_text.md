# 창원특례시의회 회의록 누비자 발언 수집·LLM 분류 메타데이터

공개 회의록의 누비자 발언 수집, 코드북 분류, 모형 간 일치도, 호출 비용의 재현용 기록.

## 1. 목적

- 창원특례시의회 회의록에서 누비자·공영자전거 언급 발언의 수집 절차 정리
- LLM 코드북 분류 결과(쟁점·입장·연도)와 두 모형 일치도의 고정
- 호출 비용과 중단 후 이어 실행 기록의 보존

## 2. 원자료

- 공개 출처 페이지: https://council.changwon.go.kr/svc/cms/mnts/MntsLatelyList.do
- 수집 스크립트: `scripts/collection/civic_text_collect.py`
- 목록 확보: 같은 사이트의 색인어 검색 `/svc/cms/mnts/MntsKeywordSearch.do` (회의 구분·회수 전체, POST)
- 원문 저장: `/cms/mntsViewer.do?mntsId=` (회의 번호)
- 접근: 로그인·캡차 없는 공개 페이지만
- 요청 간격 2.5초, `robots.txt` 확인
- 연결 실패 시 최대 4회, 대기 10초·20초·30초
- 기존 원문 파일 덮어쓰기 금지. 같은 회의의 확정본이 있으면 임시본 미사용
- 검색어: 누비자, 공영자전거
- 검색 대수: 3대(2018.7~2022.6), 4대(2022.7~2026.6), 5대(2026.7~). 설정 기간과 겹치는 대수
- 검색 기간 설정: 2020-01-01 ~ 2026-10-17
- 기간 안의 검색 결과를 회의 번호 기준으로 합침
- 발언 단위: 원문 발언 블록(SPKR)
- 발췌: 검색어가 있는 문단과 앞뒤 1문단. 떨어진 구간은 `[중략]`
- 직함이나 이름에만 검색어가 있는 발언은 결과에서 제외
- 결과 파일: `data/processed/civic_text/nubija_utterances.csv`
- 열 8개: `doc_id`, `회의일`, `회의명`, `회차`, `발언자 직위`, `발언 원문`, `출처 URL`, `수집시각`
- 행 수: 671 (헤더 제외)
- 발언이 있는 회의: 132 (`doc_id`의 회의 번호 기준. 회의일과 회의명 조합도 132)
- 회의일 범위: 2020-04-28 ~ 2026-09-17
- 수집시각 범위: 2026-10-17T12:07:25+09:00 ~ 2026-10-17T14:02:03+09:00
- 행별 출처 URL: 뷰어 주소. 안건 앵커가 있으면 해시 부착

연도별 발언 행 수 (회의일 기준, 분류 전 원자료):

| 연도 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 발언 수 | 134 | 126 | 95 | 85 | 95 | 92 | 44 |

### 개인정보

- 분류 프롬프트 구성: `[번호] (발언자 직위) 발언 원문 앞 1200자`
- 발언자 이름 미포함
- 수집 CSV에 이름 열 없음. 직위 열만 보존

## 3. 분류 방법

- 분류 스크립트: `scripts/ai/classify_council_llm.py`
- 호출 공통부: `scripts/ai/llm.py`
- 입력: 위 CSV 671행
- 분류 번호: CSV 행 순번(0부터). 회의 문서 번호와 별개
- 출력 폴더: `data/processed/civic_text/llm/`
  - `raw_haiku.jsonl`, `raw_sonnet_sample.jsonl` (원응답)
  - `codes_haiku.csv`, `codes_sonnet_sample.csv` (분류표)
  - `utterances_coded.csv` (발언과 1차 분류 결합)
  - `summary.json` (집계·일치도)

### 코드북 11개

- 관련: 누비자(공영자전거) 정책·운영에 대한 실질 내용
- 비관련: 인사·호명, "답변드리겠습니다" 같은 형식 발언, 다른 주제 속 지나가는 예시
- 쟁점: 관련일 때만. 최대 2개. 중심 쟁점을 앞에 배치. 비관련이면 빈 목록

| 코드 | 범위 |
|---|---|
| 재배치 | 자전거 쏠림·부족, 재배치·배송 차량·인력, 거치대가 비거나 가득 참 |
| 정비 | 고장·정비·노후·자전거 교체·관리 품질 |
| 확충 | 터미널·거치대 신설·이전·위치, 서비스 지역 확대 |
| 이용 | 이용 실적·수요·이용률 증감·회원 |
| 재정 | 예산·적자·운영비·요금·수익 |
| 안전 | 사고·안전·보험·자전거도로 안전 |
| 연계 | 버스·철도 등 대중교통 연계, 자전거도로망, 교통정책 전반 |
| 형평 | 외곽·소외지역·교통약자·고령자의 접근 |
| 환경 | 탄소·기후·친환경 효과 |
| 관광 | 관광·여가·홍보·행사 |
| 기타 | 위에 없는 내용 |

코드북 밖 쟁점은 제거 후 최대 2개만 유지.

### 입장 4개

- 문제제기
- 개선요구
- 현황설명
- 기타
- 네 값 밖 응답의 기록 값: 기타

### 호출

- 기본 경로: Claude Code CLI `claude -p`
- 옵션: 도구 없음, 빈 MCP 설정, 세션 비유지, 제한 시간 300초, JSON 출력
- 시스템 지시: 지방의회 회의록 발언의 코드북 분류. 설명 없는 JSON 배열만
- `ANTHROPIC_API_KEY`가 있으면 SDK 직접 호출. 그 경로의 `cost_usd`는 빈 값
- 이번 원응답의 `cost_usd`는 27행·4행 모두 숫자. 실행 경로: CLI
- SDK용 별칭 대응: `haiku` = `claude-haiku-5-5`, `sonnet` = `claude-sonnet-5-5`
- CLI에 넘긴 모형 인수: 1차 `haiku`, 2차 `sonnet`
- 원응답에 남은 실제 모형: `claude-haiku-5-5` 27행, `claude-sonnet-5-5` 4행
- 응답 처리: 첫 JSON 배열 추출. 코드 펜스 허용

### 배치·표본·재시도

- 배치 크기: 25건
- 1차: Haiku 전수 671건. 표식 `haiku`
- 2차: Sonnet 무작위 100건. seed 42 (`random_state=42`). 번호 오름차순 후 분류. 표식 `sonnet_sample`
- 배치당 최대 3회
- 재시도 조건: 호출 오류, JSON 형식 오류, 입력 번호 누락
- 재시도 간격: 2초
- 3회 실패 시 해당 배치에서 종료
- 원응답 JSONL이 있으면 이미 파싱된 번호는 건너뛰고 이어서 실행
- 파일 추가 시점: 성공한 배치만

### 일치도 계산

- 대상: 1차 전수와 2차 100건의 번호 결합
- 관련성 일치율: 표본 100건에서 관련 여부 일치 비율
- 관련성 κ: 이진 코헨 κ. 우연 일치율 = 두 코더 양성 비율의 곱 + 음성 비율의 곱
- 주제 일치율: 양쪽 모두 관련인 발언에서 쟁점 목록의 첫 값(중심 쟁점) 일치 비율. 결과 필드 `primary_code_agreement`
- 쟁점별 κ: 양쪽 모두 관련인 발언에서 해당 쟁점 포함 여부. 두 코더 양성 건수 합이 3 미만이면 제외
