# 재배치 시뮬레이션(관측 대여 재생형 디지털 트윈)

작성: 2026-10-17 Claude Code. 코드 `scripts/analysis/simulate_rebalancing.py`(엔진), `run_rebalancing_experiments.py`(실험), `estimate_observed_truck_km.py`(현재 운영 거리 추정), 시험 `tests/test_simulate_rebalancing.py`. 출력 `data/processed/rebalancing_sim/`.
Codex의 '조건부 시작버퍼'(`support_policy_evaluation.md`)를 대체하는 주 정책 실험. 시작버퍼는 하루 단위로 재고가 이어지지 않고 차량·이동 대수와 연결되지 않아 운영 언어로 설명하기 어려움 → 재고가 날마다 이어지는 재생형으로 전환. 시작버퍼의 q 정의(아침 최소 필요 대수)는 목표값으로 계승

## 1. 질문
- 같은 차량(밤당 이동 대수 예산)으로 관측 대여를 얼마나 지원하는가
- AI 예측이 경험 규칙보다 같은 예산에서 더 많이, 또는 같은 성과를 더 적은 이동(차량 km·탄소)으로 달성하는가
- 취약 거점(버스·생활시설 접근성 하위)에 아침 최소 대수를 보장하면 그 동네의 빈 시간이 얼마나 줄고, 전체 성과 비용은 얼마인가
- 차량을 줄이면 어느 동네가 먼저 서비스를 잃는가

## 2. 엔진 규칙
- 수요: 실제 관측 대여(출발 거점·시각)와 반납(도착 거점·시각)을 시간순 재생. 그 시각 재고가 0이면 대여 실패, 그 반납도 생기지 않음
- 재배치: 매일 02:00(01~04시 대여 거의 없음) 밤당 예산 M대 이내
- 배치 규칙(모든 전략 공통): 거점별 그날 필요 대수 예측 λ로 'k번째 자전거가 필요할 확률' P(Q≥k)를 포아송 꼬리로 근사 → 가치가 가장 큰 곳에 놓고 손실이 가장 작은 곳에서 가져오는 탐욕 배치(이득이 0 이하이면 중단). 형평 전략은 먼저 취약 거점을 최소 대수까지 채움
- 목표값 q: 그날 02~23시 시간대 대여·반납으로 계산한 max_k(Σ대여 − Σ이전 시간 반납), 같은 시간 안 대여 우선
- 거점·일 대상: 직전 28일 대여·반납 1건 이상(누출 없음), 운영센터 제외
- 시작 재고: 기간 첫날 02:00 각 자전거의 '다음 대여 출발 거점'(7일 이내), 진행 중 이용은 반납 예정으로 처리
- 차량 거리: 밤마다 수거·배치 목록을 적재 용량 20대 탐욕 경로(가장 가까운 가능 지점, 운영센터 243 출발·복귀)로 이은 직선거리. 도로 우회계수는 후처리 민감도
- 지표: 관측 대여 성공률(전체·취약·비취약·고지대), 거점 빈 시간(05~24시, 기간 내내 대상인 거점), 밤당 이동 대수, 차량 경로 km

## 3. 한계(보고서 표기)
- 관측된 대여만 재생 → 빈 거점에서 포기된 수요(검열)는 반영 못 함. 성공률은 '실제로 일어난 이용을 지원했는가'의 지표
- 거치대 용량·주간 재배치·정비·차량 대수 제약 없음(야간 1회 재배치 단순화)
- 차량 거리는 탐욕 경로 직선거리 → 실제 운행거리 아님(전략 간 상대 비교용)
- 실제 운영은 모든 관측 대여를 지원한 상태(성공률 100%, 낮 재배치 포함)이므로 시뮬레이션 성공률을 실제 운영과 직접 비교하지 않음

## 4. 사전 고정(`policy_lock_v1.json`, SHA256 `ed2865c0…b4de403`)
- 시험기간 2025-01-01~06-30 결과를 보기 전 고정. 검증기간 2024-10-01~12-31은 전략별 λ = α·q̂ + β의 α∈{0.8,1,1.25,1.5,2}, β∈{0,1,2} 선택에만 사용(기준 예산 1,500대/밤)
- 전략: 재배치 없음 / 경험 규칙(최근 4주 같은 요일) / 경험 규칙+취약 최소 2대 / AI / AI+취약 최소 2대(주 형평 정책) / AI+당일 날씨(기상예보 가정 상한) / 그 형평판 / 완전 예지(상한)
- 민감도(1,500대): 보장 3대, 복합 취약 집단 보장, 보장 대신 취약 가치 1.5배
- 취약 집단: `station_groups.csv`(취약 165, 복합취약 49) ← `accessibility_scenarios` 잠금 정의 그대로
- 코드 해시를 잠금에 기록. 엔진 변경 시 v2 잠금을 추가하고 v1 보존
